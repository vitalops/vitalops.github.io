Autonomous coding agents that finish the job

OpenVibe is our open-source coding agent. Pip install it, give it a task in plain English, and it runs end to end. Sessions, permissions, and the same tools a human engineer would use.

The shape of the problem

Most coding assistants live inside an editor. They suggest a few lines, you accept or reject, and they step back. That is useful for the active work the engineer is already doing. It does not help with the long tail.

The long tail is the work that sits on the backlog. Dependency upgrades. Bug fixes. Tests that need to be backfilled. A migration that needs to be applied across hundreds of files. Things where the engineer would have to spend hours reading and only minutes writing.

What OpenVibe does

OpenVibe takes a task description and runs it to completion. It reads the relevant files, decides what to change, makes the change, runs the tests, fixes failures, and comes back with a pull request and a clear log of everything it did.

It can run as a long-lived server or as a one-shot command:

# start the server
openvibe serve

# one-shot run
openvibe run "fix the failing tests in the auth module"

# list sessions
openvibe session list
openvibe session show <session-id>

What you keep control over

  • Pluggable model backends. The agent talks to the model through a thin abstraction. Switch between Anthropic, OpenAI, or anything else in a config file.
  • Permission controls. For each tool the agent can use, you decide whether it can use it freely, has to ask, or cannot use it at all. Bash. Write. Network. The defaults are conservative.
  • Persistent sessions. Every run is recorded. You can list past sessions, replay them, or pick one up where it left off.
  • MCP integration. Plug in any Model Context Protocol server to give the agent a new capability without changing its code.

How teams use it

The pattern that has worked best is to pair OpenVibe with a queue. Bug reports come in. OpenVibe picks them up overnight. By morning, the team has a queue of pull requests to review. Most are real fixes. Some are partial work with a clear note about where the agent got stuck. The team merges what is ready and gives feedback on the rest.

Another pattern is to point OpenVibe at a long-running migration. Framework upgrades. API changes. Anything that touches many files in a repetitive way. OpenVibe goes file by file, applies the change, runs the relevant tests, and flags anything that needs human judgement.

Why it is open source

We use OpenVibe ourselves on customer projects. We open-sourced it because tools like this get better when more people are running them, and because the cost of a great coding agent should not be locked behind a per-seat SaaS price.

Engineers can run it on their own machine, with their own model keys, against their own code, without anything leaving their environment. That matters when the codebase is sensitive.

Where it fits in the stack

OpenVibe is the agent. Temenos is the sandbox we run it in when we want to run a thousand of them in parallel safely. Coherence is the memory layer for sessions that span days, not minutes. The three together are what makes autonomous coding actually feasible.
